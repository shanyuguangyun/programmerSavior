01先建立整体认识

Spring 不是某一个单独的功能，而是一套围绕 Java 对象和基础设施的生态。 它最核心的价值是：帮你管理对象、组织依赖、统一处理横切逻辑，并简化 Web 和数据访问。

IoC 容器

创建、组装和管理 Bean，让对象不再到处 new。

AOP

把日志、事务、权限等横切逻辑从业务代码中抽离。

数据访问

JdbcTemplate、MyBatis、JPA 等统一接入数据库。

Spring MVC

把 HTTP 请求映射到 Controller 方法并返回 JSON。

测试支持

提供 Spring 上下文、MockMvc 等测试基础设施。

Spring Boot

在 Spring 之上做自动配置、Starter 和内嵌服务器。

先分清：Spring Framework 是核心框架；Spring Boot 是构建 Spring 应用的方式，它并没有替代 Spring。日常说“写 Spring 项目”，通常指的是 Spring Boot + Spring MVC + 数据访问框架。

02IoC 与 DI：对象交给容器管理

IoC（控制反转）指对象的创建和依赖装配交给 Spring 容器，而不是业务代码自己 new。 DI（依赖注入）是实现 IoC 的方式：容器把依赖对象传进来。

推荐写法：构造器注入

@Service
public class AuthService {

    private final PsAccountMapper accountMapper;

    public AuthService(PsAccountMapper accountMapper) {
        this.accountMapper = accountMapper;
    }
}

当类只有一个构造器时，Spring 4.3+ 会自动注入，不需要额外写 @Autowired。依赖声明为 final，对象创建后不会被替换， 更容易测试，也能避免空指针。

三种注入方式

方式 特点 建议
构造器注入 依赖不可变，启动时就能发现缺失依赖 首选
Setter 注入 适合可选依赖，但对象可能处于不完整状态 谨慎使用
字段注入 写法短，但隐藏依赖，单元测试不方便 尽量不用

ApplicationContext

ApplicationContext 是 Spring 的应用上下文，负责启动容器、加载 Bean 定义、完成依赖注入，并提供事件、国际化、资源加载等能力。Spring Boot 启动时， 本质上也是在创建并刷新一个应用上下文。

03Bean 与常用注解

Bean 是由 Spring 容器创建和管理的对象。最常用的声明方式有两种： 在类上使用组件注解，或者在配置类里使用 @Bean 方法。

注解 用途 备注
@Component 通用组件 其他 stereotype 注解的基础
@Service 业务层 语义化，本质仍是组件
@Repository 数据访问层 可参与持久层异常转换
@Controller Web 控制器 通常返回视图
@RestController REST 控制器 @Controller + @ResponseBody
@Configuration 配置类 可以声明多个 @Bean
@Bean 声明 Bean 适合第三方类或需要手动装配的对象

@Configuration 与 @Bean

@Configuration
public class AppConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

组件扫描默认从启动类所在包向下查找。启动类放在 com.example，那么 com.example.service 会被扫描； 放到别的包则不会，除非手动配置扫描范围。

04Bean 生命周期与作用域

可以把单例 Bean 的生命周期简化成下面几个阶段：

实例化→ 依赖注入→ 初始化前→ @PostConstruct→ 使用→ @PreDestroy 
@Component
public class CacheWarmer {

    @PostConstruct
    public void init() {
        // 容器完成依赖注入后执行
    }

    @PreDestroy
    public void destroy() {
        // 容器关闭 / Bean 销毁前执行
    }
}

作用域

作用域 说明
singleton 默认值，一个容器内只有一个实例
prototype 每次获取都创建新实例，容器不负责销毁
request 每个 HTTP 请求一个实例，仅 Web 环境
session 每个 HTTP Session 一个实例，仅 Web 环境
application 整个 ServletContext 生命周期一个实例
注意：单例 Bean 默认会被多个线程共享。尽量不要在单例 Bean 里保存可变请求状态，把请求数据放在方法局部变量或参数里，避免线程安全问题。

05配置与 Profile

Spring Boot 通常使用 application.yml 或 application.properties。简单值可以用 @Value， 一组结构化配置更适合 @ConfigurationProperties。 

app:
  upload:
    max-size-mb: 2
    allowed-extensions:
      - html
      - htm
@ConfigurationProperties(prefix = "app.upload")
public class UploadProperties {

    private int maxSizeMb = 2;
    private List<String> allowedExtensions = new ArrayList<>();

    // getter / setter
}

还需要让 Spring 发现这个配置类，例如加上 @Component， 或在启动类使用 @EnableConfigurationProperties / @ConfigurationPropertiesScan。

Profile

用 spring.profiles.active 或环境变量切换配置，例如 application-dev.yml、application-prod.yml。 常见做法是通过环境变量覆盖数据库账号、密码等敏感配置，不要把生产密码提交到仓库。

配置优先级：不需要背完整顺序，先记住“外部配置通常优先于打包进 jar 的配置”。命令行参数和环境变量适合部署时覆盖，本地默认值放在 application.yml。

06AOP：横切逻辑抽出来

AOP（面向切面编程）用来处理日志、事务、权限、性能统计这类分散在多个方法里的 公共逻辑。Spring AOP 基于代理实现，常见的是 JDK 动态代理或 CGLIB 代理。

概念 含义
切面 Aspect 横切逻辑的模块，例如日志切面
连接点 Join Point 程序执行过程中可以插入逻辑的点
切点 Pointcut 匹配哪些连接点，例如某个包下的所有方法
通知 Advice 在切点前后执行的动作，如 Before、Around 
@Aspect
@Component
public class LogAspect {

    @Around("execution(* com.example.service..*(..))")
    public Object log(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return joinPoint.proceed();
        } finally {
            long cost = System.currentTimeMillis() - start;
            System.out.println(joinPoint.getSignature() + " cost=" + cost + "ms");
        }
    }
}
代理自调用：同一个类里 this.methodB() 调用 methodB()，不会再次经过 Spring 代理，因此 @Transactional、自定义 AOP 等可能失效。把方法拆到另一个 Bean， 或通过代理对象调用。

07Spring MVC 与 REST

一次典型的 HTTP 请求会经过下面这条链路：

浏览器→ DispatcherServlet→ HandlerMapping→ Controller→ Service→ Repository→ 数据库

DispatcherServlet 是前端控制器，负责把请求分发给对应的 Handler。@RestController 的返回值会经过消息转换器序列化成 JSON。 

@RestController
@RequestMapping("/api/posts")
public class PostController {

    private final PostService postService;

    public PostController(PostService postService) {
        this.postService = postService;
    }

    @GetMapping
    public List<Post> list(@RequestParam String path) {
        return postService.listByPath(path);
    }

    @GetMapping("/{id}")
    public Post detail(@PathVariable Long id) {
        return postService.findById(id);
    }
}
注解 用途
@RequestMapping 类或方法的通用路径前缀
@GetMapping GET 请求映射
@PostMapping POST 请求映射
@RequestParam 读取查询参数或表单字段
@PathVariable 读取路径中的变量
@RequestBody 把 JSON 请求体反序列化成对象
@ResponseBody 把返回值写入响应体
参数校验：在 DTO 上使用 @NotBlank、 @Size 等约束，并在 Controller 参数上加 @Valid。配合全局异常处理，可以统一返回 400。

08数据访问与事务

Spring 支持多种数据访问方式：JdbcTemplate、MyBatis、 JPA / Hibernate 等。无论选择哪种，通常都会分成 Controller → Service → Mapper / Repository 三层。

@Transactional

@Service
public class PostService {

    @Transactional
    public void createPost(Post post) {
        postMapper.insert(post);
        // 同一事务内继续写其他表
    }

    @Transactional(readOnly = true)
    public List<Post> list() {
        return postMapper.selectList(null);
    }
}
  • 默认只对 运行时异常和 Error 回滚；受检异常需要配置 rollbackFor。
  • 方法被外部 Bean 调用时事务代理才会介入；同类自调用会绕过代理。
  • 事务方法通常应是 public，不要吞掉异常后继续返回成功。
  • 查询可以加 readOnly = true，表达只读意图，部分驱动会据此优化。
常见错误：业务代码里 catch 了异常却没有重新抛出，事务管理器认为方法正常结束， 于是不会回滚。要么不 catch，要么处理完后抛出运行时异常或调用 TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()。

09Spring Boot：约定优于配置

Spring Boot 的核心目标是让 Spring 应用更容易启动。它提供 Starter 依赖、 自动配置、外部化配置和内嵌 Web 服务器。 

@SpringBootApplication
public class Application {

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}

@SpringBootApplication 可以理解为三个注解的组合：

  • @SpringBootConfiguration：标记配置类。
  • @EnableAutoConfiguration：根据 classpath 自动装配。
  • @ComponentScan：扫描当前包及子包。

Starter

Starter 用途
spring-boot-starter-web Spring MVC、JSON、内嵌 Tomcat
spring-boot-starter-validation Bean Validation 参数校验
spring-boot-starter-test JUnit、Mockito、AssertJ、Spring Test
spring-boot-starter-data-jpa JPA / Hibernate 数据访问

启动类默认会扫描自己所在包和子包。把启动类放在项目根包下，是避免 “Bean 找不到”的最简单方式。

10测试

Spring Boot 测试通常分两层：只测 Web 层，或者启动完整应用上下文。 

@SpringBootTest
class AuthServiceTest {

    @Autowired
    private AuthService authService;

    @Test
    void shouldLoginWithCorrectPassword() {
        // 这里通常会配合 Mock 或测试数据库
    }
}
@WebMvcTest(PostController.class)
class PostControllerTest {

    @Autowired
    private MockMvc mockMvc;
}
  • @SpringBootTest：启动完整上下文，适合集成测试，速度较慢。
  • @WebMvcTest：只加载 MVC 相关组件，适合 Controller 测试。
  • MockMvc：不启动真实 HTTP 端口，也能验证路由、状态码和 JSON。
  • 依赖替换可以使用 Mockito；不同 Spring Boot 版本推荐的 mock 注解略有差异。

11新手最容易踩的坑

  • 启动类位置太深：组件扫描只覆盖当前包及子包。
  • 字段注入滥用：依赖不清晰，单元测试困难，优先构造器注入。
  • 同类自调用：AOP 和事务代理不生效，方法要跨 Bean 调用。
  • 吞异常：@Transactional 默认不会因为被 catch 的异常而回滚。
  • 单例保存请求状态：多线程会互相覆盖，保持 Bean 无状态。
  • 循环依赖：先检查职责划分，不要只靠延迟注入掩盖设计问题。
  • 把配置写死：数据库地址、密码等应使用环境变量或外部配置。
  • 认为 Spring Boot 等于 Spring：Boot 只是自动配置和启动方式。

12建议的学习顺序

  1. 先理解 IoC / DI，能手写一个构造器注入的 Service。
  2. 再学 Bean 声明、扫描范围、生命周期和作用域。
  3. 掌握 Spring MVC 的请求映射、参数绑定和统一异常处理。
  4. 接一个数据库，理解 Mapper / Repository、事务和连接池。
  5. 学习 AOP，知道事务和日志为什么能自动生效。
  6. 最后用 Spring Boot 把配置、Starter、测试和部署串起来。
一句话总结：Spring 帮你管理对象和基础设施，Spring Boot 帮你更快地启动和配置 Spring。先把 IoC、MVC、事务这三条线走通，其他模块都是在此基础上扩展。
